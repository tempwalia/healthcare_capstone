# Health Microservice API — Full Rebuild Blueprint

This document is a **self-sufficient specification** to rebuild the `healthcare_capstone` project from an empty
folder. It was generated by analyzing every source file in the original repository (config, database,
auth, all 15 models, all schemas, all 9 routers, Alembic setup, Docker, scripts, tests). You only need
to supply your own `.env` file — everything else (project structure, exact code, migration workflow,
Docker setup) is spelled out below.

> **How to use this doc**: work top-to-bottom. Each section gives you the exact file path and the exact
> code to put in it. By the end you'll have a working, tested, containerized FastAPI service identical
> in structure to the original.

---

## 1. Tech Stack

| Concern | Choice |
|---|---|
| Language | Python ≥ 3.13.3 |
| Web framework | FastAPI (async) |
| ORM | SQLAlchemy 2.x (async engine, `AsyncSession`) |
| DB driver | `asyncpg` (Postgres), `aiosqlite` (tests / offline) |
| Migrations | Alembic (async-aware `env.py`) |
| Auth | OAuth2 Password Flow + JWT (`python-jose`), `passlib[bcrypt]` for hashing |
| Config | `pydantic-settings` reading a `.env` file |
| Package manager | `uv` (with a `requirements.txt` fallback for plain `pip`) |
| API docs | Swagger UI (`/docs`), ReDoc (`/redoc`) — automatic via FastAPI |
| MCP integration | `fastapi_mcp.FastApiMCP` mounted at `/mcp` (exposes every route as an MCP tool) |
| Containerization | Docker + docker-compose (api + postgres) |
| Testing | `pytest` + `pytest-asyncio` + `httpx.AsyncClient` against an in-memory SQLite DB |

**No custom application logging exists in the original project.** The only logging configuration is
Alembic's stdlib logging block in `alembic.ini` (root/sqlalchemy/alembic loggers → stderr) plus
whatever Uvicorn prints by default (access logs, startup banner). There is no request-ID middleware,
no structured/JSON logging, and no app-level logger module. Section 12 documents this honestly and
gives you an optional, drop-in logging module if you want proper logging in your learning version.

security primitives), `database/` (engine/session/Base), `auth/` (JWT + password hashing, thin
wrappers around `core/security.py`).

## 4. Configuration (`app/core/config.py`)

```python
from pydantic_settings import BaseSettings
from pydantic import Field
from typing import Optional


class Settings(BaseSettings):
    app_name: str = "Health Microservice API"
    debug: bool = False
    version: str = "1.0.0"

    # Database
    database_url: str = Field(..., env="DATABASE_URL")

    # JWT
    secret_key: str = Field(..., env="SECRET_KEY")
    algorithm: str = "HS256"
    access_token_expire_minutes: int = 30

    # CORS
    backend_cors_origins: list[str] = [
        "http://localhost:3000",
        "http://localhost:5000",
        "http://localhost:8080",
    ]

    class Config:
        env_file = ".env"
        case_sensitive = False


settings = Settings()
```

`database_url` and `secret_key` are **required** (`Field(...)`) — the app refuses to start without
them. Everything else has a sane default. `Settings` is instantiated once at import time as a module-
level singleton (`settings`) and imported everywhere else needs config — this is the only place `.env`
is read.

### `.env.example`
```
DATABASE_URL=postgresql+asyncpg://username:password@localhost/health_db
SECRET_KEY=your-super-secret-key-here-change-in-production
DEBUG=False
```

Your real `.env` (git-ignored) follows the same three keys. Note the driver prefix:
`postgresql+asyncpg://` — plain `postgresql://` won't work with the async engine.

## 5. Database Layer

### `app/database/base.py`

```python
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy import MetaData

# Naming convention for constraints
naming_convention = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}

metadata = MetaData(naming_convention=naming_convention)
Base = declarative_base(metadata=metadata)
```

The explicit `naming_convention` matters: without it, Alembic autogenerate produces unpredictable,
auto-hashed constraint names (e.g. `fk_abc123`) that differ every time you regenerate, making diffs
noisy and downgrades fragile. With it, every constraint gets a deterministic, greppable name like
`fk_appointments_patient_id_patients`.

### `app/database/session.py`

```python
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker
from app.core.config import settings

engine = create_async_engine(settings.database_url, echo=settings.debug, future=True)

async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)


async def get_async_session() -> AsyncSession:
    async with async_session() as session:
        try:
            yield session
        finally:
            await session.close()
```

`echo=settings.debug` — when `DEBUG=True` in `.env`, every SQL statement SQLAlchemy runs is printed to
stdout. This is the closest thing to "database logging" in the original project. `expire_on_commit=False`
means ORM objects stay usable (attributes readable) after `commit()` without triggering a fresh
`SELECT` — important because routes do `db.add(obj); await db.commit(); await db.refresh(obj); return obj`
and then FastAPI serializes `obj` via the Pydantic response model.

### `app/api/dependencies/database.py`
Thin re-export so routes import from `api.dependencies` rather than reaching into `database` directly:
```python
from app.database.session import get_async_session

__all__ = ["get_async_session"]
```

## 6. Authentication & Security

Three layers: `core/security.py` (raw primitives) → `auth/*.py` (re-exports + JWT-specific logic) →
`api/dependencies/auth.py` (FastAPI `Depends()` glue). This split exists so `core/` has zero FastAPI
imports (pure, testable functions) while `api/dependencies/` is where request/DB/HTTP concerns live.

### `app/core/security.py`
```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")


def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)


def get_password_hash(password: str) -> str:
    return pwd_context.hash(password)
```

### `app/auth/password_utils.py`
```python
from app.core.security import verify_password, get_password_hash

__all__ = ["verify_password", "get_password_hash"]
```

### `app/auth/jwt_handler.py`
```python
from datetime import datetime, timedelta
from typing import Optional
from jose import JWTError, jwt
from app.core.config import settings


def create_access_token(data: dict, expires_delta: Optional[timedelta] = None):
    to_encode = data.copy()
    if expires_delta:
        expire = datetime.utcnow() + expires_delta
    else:
        expire = datetime.utcnow() + timedelta(
            minutes=settings.access_token_expire_minutes
        )

    to_encode.update({"exp": expire})
    encoded_jwt = jwt.encode(
        to_encode, settings.secret_key, algorithm=settings.algorithm
    )
    return encoded_jwt


def verify_token(token: str) -> Optional[str]:
    try:
        payload = jwt.decode(
            token, settings.secret_key, algorithms=[settings.algorithm]
        )
        username: str = payload.get("sub")
        if username is None:
            return None
        return username
    except JWTError:
        return None
```

The JWT payload's only claim is `sub` (the username) plus `exp`. No refresh tokens, no scopes/roles in
the token — authorization is all-or-nothing (authenticated vs not) once past `get_current_active_user`.

### `app/api/dependencies/auth.py`
```python
from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from app.api.dependencies.database import get_async_session
from app.auth.jwt_handler import verify_token
from app.models.user import User

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="auth/login")


async def get_current_user(
    token: str = Depends(oauth2_scheme), db: AsyncSession = Depends(get_async_session)
) -> User:
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )

    username = verify_token(token)
    if username is None:
        raise credentials_exception

    result = await db.execute(select(User).where(User.username == username))
    user = result.scalar_one_or_none()

    if user is None:
        raise credentials_exception

    return user


async def get_current_active_user(
    current_user: User = Depends(get_current_user),
) -> User:
    if not current_user.is_active:
        raise HTTPException(status_code=400, detail="Inactive user")
    return current_user
```

`get_current_active_user` is the dependency every protected route uses
(`current_user: User = Depends(get_current_active_user)`). It's never actually referenced inside route
bodies in the original code — it exists purely to **gate access**: FastAPI runs the dependency chain
before the route body, and an invalid/missing/expired token raises `401` before your handler ever runs.

### `app/schemas/auth.py`
```python
from pydantic import BaseModel, EmailStr
from typing import Optional


class UserCreate(BaseModel):
    email: EmailStr
    username: str
    password: str


class UserResponse(BaseModel):
    id: int
    email: str
```

(`LoginRequest` is defined but unused — login actually uses FastAPI's built-in
`OAuth2PasswordRequestForm`, which expects `application/x-www-form-urlencoded` data with `username` and

POST, not a JSON POST, unlike every other endpoint in the API.)

### `app/api/routes/auth.py`
```python
from fastapi import APIRouter, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordRequestForm
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy import select
from app.api.dependencies.database import get_async_session
from app.schemas.auth import UserCreate, UserResponse, Token
from app.models.user import User
from app.auth.jwt_handler import create_access_token
from app.core.security import verify_password, get_password_hash

router = APIRouter(prefix="/auth", tags=["authentication"])


@router.post("/register", response_model=UserResponse)
async def register(
    user_data: UserCreate, db: AsyncSession = Depends(get_async_session)
):
    # Check if user already exists
    result = await db.execute(select(User).where(User.email == user_data.email))
    if result.scalar_one_or_none():
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST, detail="Email already registered"
        )

    result = await db.execute(select(User).where(User.username == user_data.username))
    if result.scalar_one_or_none():
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST, detail="Username already taken"
        )

    # Create new user
    hashed_password = get_password_hash(user_data.password)
    user = User(
        email=user_data.email,
        username=user_data.username,
        hashed_password=hashed_password,
    )

    db.add(user)
    await db.commit()
    await db.refresh(user)

    return user


@router.post("/login", response_model=Token)
async def login(
    form_data: OAuth2PasswordRequestForm = Depends(),
    db: AsyncSession = Depends(get_async_session),
):
    result = await db.execute(select(User).where(User.username == form_data.username))
    user = result.scalar_one_or_none()

    if not user or not verify_password(form_data.password, user.hashed_password):
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )

    access_token = create_access_token(data={"sub": user.username})
    return {"access_token": access_token, "token_type": "bearer"}
```

**Auth flow end to end:**
1. `POST /auth/register` with JSON `{email, username, password}` → checks email and username are
   unique → hashes password with bcrypt → inserts row → returns `UserResponse` (no password).
2. `POST /auth/login` with form-encoded `username`+`password` → looks up by username → verifies bcrypt
   hash → issues a JWT (`sub=username`, 30 min expiry by default) → returns `{access_token, token_type: "bearer"}`.
3. Every other endpoint requires header `Authorization: Bearer <token>` → `oauth2_scheme` extracts the
   token → `verify_token` decodes+validates it → username is looked up in the DB again (so a deleted
   user's old token stops working immediately, without needing token revocation) → `is_active` is
   checked.

## 9. Domain Models, Schemas & Routes

Every domain module (except `auth`) follows an **identical CRUD pattern**:
- Model: SQLAlchemy class with `id`, business fields, `created_at`/`updated_at` (`server_default=func.now()` / `onupdate=func.now()`).
- Schema: `XBase` (shared fields) → `XCreate(XBase)` (identical to base, used for POST) → `XUpdate`
  (all fields `Optional`, used for PUT with `exclude_unset=True` partial updates) → `XResponse(XBase)`
  (adds `id`, `created_at`, `updated_at`, `Config.from_attributes = True`).
- Route: `APIRouter(prefix="/x", tags=["x"])` with `POST /`, `GET /`, `GET /{id}`, `PUT /{id}`,
  `DELETE /{id}`, all behind `current_user: User = Depends(get_current_active_user)`.
- Two lookup styles are used interchangeably in the original: `select(Model).where(Model.id == id)`
  then `.scalar_one_or_none()`, or the shorthand `await db.get(Model, id)` — both are equivalent for
  single-PK lookups; newer domain modules (lab, referral, pharmacy, insurance, telemedicine) use
  `db.get`, the earlier ones (patients, doctors, appointments, medical-records) use `select(...).where(...)`.

### 9.6 Lab, Referral, Pharmacy, Insurance — same "simplified" pattern as Telemedicine

These four modules follow **exactly** the Telemedicine pattern above (`db.get`, full-object `PUT`,
`{"ok": True}` deletes, no cross-FK validation) — just with different models/fields/prefixes. Build
each the same way: model → matching `Base`/`Create`/`Response` schema trio (no separate `Update`
schema) → router with one CRUD block per sub-resource.

**Lab** (`app/models/lab.py`, `app/schemas/lab.py`, `app/api/routes/lab.py`, `prefix="/lab"`):
- `LabOrder` (`patient_id`, `doctor_id`, `order_date: Date`, `test_type`, `status="ordered"`, `notes`) → routes under `/lab/orders/`

## 11. Application Entrypoint (`app/main.py`)

```python
from fastapi import FastAPI
from fastapi_mcp import FastApiMCP
from app.core.config import settings
from app.middlewares.cors import add_cors_middleware
from app.api.routes import (
    auth,
    patients,
    doctors,
    appointments,
    medical_records,
    telemedicine,
    lab,
    referral,
    pharmacy,
    insurance,
)

app = FastAPI(
    title=settings.app_name,
    version=settings.version,
    description="A comprehensive health microservice API with JWT authentication",
)

# Add CORS middleware
add_cors_middleware(app)

# Include routers
app.include_router(auth.router)
app.include_router(patients.router)
app.include_router(doctors.router)
app.include_router(appointments.router)
app.include_router(medical_records.router)
app.include_router(telemedicine.router)
app.include_router(lab.router)
app.include_router(referral.router)
app.include_router(pharmacy.router)
app.include_router(insurance.router)


@app.get("/")
async def root():
    return {"message": "Welcome to Health Microservice API"}


@app.get("/health")
async def health_check():
    return {"status": "healthy", "version": settings.version}

# Create an MCP server based on this app
mcp = FastApiMCP(app)

# Mount the MCP server directly to your app
mcp.mount()
```

`FastApiMCP(app)` introspects every route already registered on `app` (hence it must run **after**
`include_router` calls) and auto-generates one MCP "tool" per endpoint, named after each route's
`operation_id`. `mcp.mount()` attaches an SSE endpoint at `/mcp`. Any MCP client (Claude Desktop,
Windsurf, Cursor, VS Code) can then call `POST /auth/login` first to get a bearer token, then connect
to `/mcp` with `Authorization: Bearer <token>` and invoke the API as tools instead of raw HTTP calls.

Note there's no `startup`/`shutdown` event handler and no lifespan context — the async engine created
in `database/session.py` is just a module-level object that lives for the process lifetime; connections
are returned to the pool automatically as each request's session closes.

## 12. Logging (honest assessment + optional addition)

**What the original project actually has:**
- `alembic.ini` configures three stdlib loggers (`root` → WARN, `sqlalchemy.engine` → WARN, `alembic`
  → INFO), all writing to `stderr` via a single `StreamHandler` with format
  `%(levelname)-5.5s [%(name)s] %(message)s`. This only affects `alembic` CLI invocations.
- `create_async_engine(..., echo=settings.debug, ...)` — when `DEBUG=True`, SQLAlchemy prints every
  SQL statement it executes to stdout. This is the closest thing to app-level logging.
- Uvicorn's own default logging (access log lines, startup/shutdown messages) when run with
  `uvicorn app.main:app`.
- **Nothing else.** No `app/core/logging.py`, no request-ID middleware, no structured/JSON logs, no log
  file rotation, no error tracking integration (Sentry etc). The README's own TODO list even says
  "Add more logging" — it's an acknowledged gap, not an oversight you're missing something about.

**Optional addition for your learning project** — if you want real logging, drop this in as
`app/core/logging.py` and call `configure_logging()` at the top of `app/main.py` before creating the
`FastAPI()` instance. It's deliberately minimal and stdlib-only, consistent with the rest of the
project's "no unnecessary dependencies" style:

```python
# app/core/logging.py
import logging
import sys
from app.core.config import settings


def configure_logging() -> None:
    level = logging.DEBUG if settings.debug else logging.INFO
    logging.basicConfig(
        level=level,
        format="%(asctime)s %(levelname)-8s [%(name)s] %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S",
        stream=sys.stdout,
    )
    logging.getLogger("sqlalchemy.engine").setLevel(
        logging.INFO if settings.debug else logging.WARNING
    )
```

Then get a logger per module the normal way (`logger = logging.getLogger(__name__)`) in any route or
service code where you want to log — e.g. inside `auth.py`'s `login`/`register` to log successful vs.
failed attempts. This is intentionally *not* what the original ships, so treat it as your own addition,
not something to claim parity with.

### `alembic/env.py` — async-aware, pulls the URL from `Settings` (not from `alembic.ini`)
```python
import asyncio
from logging.config import fileConfig
from sqlalchemy import pool
from sqlalchemy.engine import Connection
from sqlalchemy.ext.asyncio import async_engine_from_config
from alembic import context
from app.core.config import settings
from app.database.base import Base
from app.models import User, Patient, Doctor, Appointment, MedicalRecord

config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata

config.set_main_option("sqlalchemy.url", settings.database_url)


def run_migrations_offline() -> None:
    url = config.get_main_option("sqlalchemy.url")
    context.configure(
        url=url,
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
    )
    with context.begin_transaction():
        context.run_migrations()


def do_run_migrations(connection: Connection) -> None:
    context.configure(connection=connection, target_metadata=target_metadata)
    with context.begin_transaction():
        context.run_migrations()


async def run_async_migrations() -> None:
    connectable = async_engine_from_config(
        config.get_section(config.config_ini_section, {}),
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )
    async with connectable.connect() as connection:
        await connection.run_sync(do_run_migrations)
    await connectable.dispose()


def run_migrations_online() -> None:
    asyncio.run(run_async_migrations())


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```
The line `from app.models import User, Patient, Doctor, Appointment, MedicalRecord` only imports 5 of
the 15 model files by name, but because `app/models/__init__.py` unconditionally imports *all* model
modules at import time (Section 10), every table still registers on `Base.metadata` regardless of which
names are explicitly pulled into `env.py`'s namespace — this line could import just `app.models` and
work identically; it's slightly redundant but harmless.

`config.set_main_option("sqlalchemy.url", settings.database_url)` overrides whatever URL is hardcoded
in `alembic.ini` with your `.env`'s `DATABASE_URL` at runtime — meaning **you never need to hand-edit
`alembic.ini`'s URL**, just get `.env` right.

### Standard workflow
```bash
# 1. Create the database once
psql -U postgres -c "CREATE DATABASE health_db;"

# 2. Generate a migration from your current models
uv run alembic revision --autogenerate -m "Initial migration"

# 3. Apply it
uv run alembic upgrade head

# Later, after changing models:
uv run alembic revision --autogenerate -m "add X field to Y"
uv run alembic upgrade head

# Useful extras
uv run alembic downgrade -1      # revert last migration
uv run alembic current           # show current DB revision
uv run alembic history           # list all migrations
```

The original repo's migration history (for reference — yours will differ since it's a fresh app):
`4546689d8c2d` (initial) → `2d34c4e3ebb5` (enhance models) → `a702016c224d` (add new health-sector
feature models) → `1b37c2542f97` (add new health-sector feature models, round 2). This tells you the
project was built incrementally: core (user/patient/doctor/appointment/medical_record) first, then the
"feature" modules (telemedicine/lab/referral/pharmacy/insurance/etc.) added across two later migrations.
**Recommended approach for your rebuild**: don't try to write all 15 models then one giant migration —
build and migrate incrementally the same way (core entities → auth-protected CRUD → verify it works →
add the next domain module → new migration), it makes debugging FK/constraint errors far easier.

`uv sync --frozen` in the build layer (before copying app code) means dependency installation is

you'd drop the volume mount and `--reload`, and move the `SECRET_KEY`/`DATABASE_URL` into a `.env`

**Key testing pattern**: `StaticPool` + `check_same_thread: False` on an in-memory SQLite engine keeps
a single persistent connection alive across the whole test (in-memory SQLite DBs are normally

talk directly to the ASGI app in-process (no real network socket / running server needed).

## 18. Step-by-Step Build Order

Follow this order to avoid FK errors and keep every step testable:

1. Scaffold the repo (Section 2 tree), `uv init`-equivalent `pyproject.toml` (Section 3), `.env` from
   `.env.example` (Section 4).
2. `uv sync` to create `.venv` and `uv.lock`.
3. Build `core/config.py`, `database/base.py`, `database/session.py` (Sections 4–5). Sanity check:
   `uv run python -c "from app.core.config import settings; print(settings.database_url)"`.
4. Build `core/security.py`, `auth/*.py`, `api/dependencies/*.py` (Section 6).
5. Build `models/user.py`, `schemas/auth.py`, `api/routes/auth.py`, wire into a minimal `main.py`
   (just the auth router + `/` + `/health`) (Section 7, 11 partial).
6. `CREATE DATABASE health_db;` in Postgres, write `alembic.ini` + `alembic/env.py` (Section 13),
   `alembic init alembic` first if starting fresh (then replace the generated `env.py` with the async
   version above), run `alembic revision --autogenerate -m "create users table"`, `alembic upgrade head`.
7. `uv run uvicorn app.main:app --reload --port 5000`, hit `/docs`, register + login a test user to
   confirm the auth loop works end-to-end before adding any other domain.
8. Add Patients → Doctors → Appointments → Medical Records one at a time (Section 9.1–9.4), each time:
   model → schema → route → register router in `main.py` → `alembic revision --autogenerate` →
   `alembic upgrade head` → manually verify in `/docs`.
9. Add the "simplified" pattern modules — Telemedicine → Lab → Referral → Pharmacy → Insurance
   (Section 9.5–9.6) — same loop each time.
10. Add `fastapi_mcp` mounting last (Section 11) once the REST surface is stable, so `operation_id`s
    are finalized before anyone starts relying on MCP tool names.
11. Add `middlewares/cors.py` (Section 8) whenever you first need to call the API from a browser-based
    frontend.
12. Write `tests/conftest.py` + one test file per domain (Section 16) as you go, not all at the end —
    it's much easier to write `test_patients.py` right after building patients than to reconstruct the
    fixtures later.
13. Add Docker (Section 14) and scripts (Section 15) once the app runs locally — containerizing broken
    code just hides the errors.
14. Optionally add `app/core/logging.py` (Section 12) and/or build out the bonus models (Section 10) as
    your own extension work — this is exactly the part the original project leaves undone.

## 19. Known Gaps in the Original (things you could legitimately improve as learning exercises)

- No refresh tokens — JWTs just expire after 30 minutes with no renewal flow.
- No role-based access control despite `Role`/`Permission` models existing — every authenticated user
  can CRUD every resource, there's no "doctor can only see their own patients" scoping.
- No rate limiting on `/auth/login` (brute-force risk).
- `PatientUpdate`/`DoctorUpdate`/`MedicalRecordUpdate` exist for partial updates, but the "simplified"
  modules (telemedicine/lab/referral/pharmacy/insurance) reuse the `Create` schema for `PUT`, so
  clients must resend every field on update — no partial-update support there.
- No pagination metadata (total count, next/prev links) — just raw `skip`/`limit` with no way to know
  how many total records exist.
- No soft-deletes — `DELETE` is a hard SQL `DELETE`.
- No app-level logging (Section 12) or error tracking.
- No health check that actually pings the database — `/health` returns "healthy" even if Postgres is down.
- `AuditLog`, `Notification`, `Reminder`, `Message`, `Feedback`, `Survey`, `ConsentForm`,
  `ConsentHistory`, `WearableDevice`, `DeviceData`, `RemoteMonitoringLog`, `EducationalResource` models
  exist in the schema but have zero API surface — good scope for "add a new feature module" practice
  using Section 9's pattern.
